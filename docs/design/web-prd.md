# 广州学途 · Web 端产品需求文档（PRD）

> 本文档定义「广州学途」**Web 网站**（响应式，同时覆盖手机浏览器与电脑浏览器）的产品功能需求与业务规则。
> 界面视觉、组件样式、响应式断点见同级文件 `web-ui-spec.html`（设计稿）。
> 适用范围：广州七区（荔湾 / 越秀 / 海珠 / 天河 / 白云 / 黄埔 / 番禺）幼升小、小升初、初升高升学路径调研的 Web 端呈现。
> 版本：基于小程序 PRD `school-search-prd.md`（R6–R12）与小程序 UI 稿 `school-search-ui-spec.html` 对齐改写。
>
> **与小程序版的关系（必读）**
> - **对齐项（原样保留）**：全部产品功能逻辑、业务规则、数据字段真源（`data/*.json`）、学段配色口径、标签展示规则、表单（表格）统一规范、招生方式枚举、筛选「行政区过滤 / 板块·地铁仅定位」口径、多学段 tab 规则等。Web 端不做业务语义上的删减。
> - **转换为 Web 交互的项**：导航（原生 tabBar → 响应式导航）、定位（`wx.getLocation` → Web Geolocation）、学校卡（半窗手势展开 → 抽屉 + 详情页）、筛选面板（顶部通栏半窗 → 弹层 / 侧栏 / 底部抽屉）、搜索（独立搜索页 → 顶部搜索 + 联想下拉 / 搜索覆盖层）、列表表格（移动端卡片化 / 横滑降级）。本文档对每一项给出 Web 实现口径。
> - **明确舍弃的小程序专有项**：微信右上角系统胶囊（··· / ⊕）、微信原生 tabBar、系统键盘区（`wx.showKeyboard` 类）、`wx.getLocation` 的「30 天拒绝静默期」逻辑、半窗卡片的「上滑跟手展开 / 下滑关闭 / 横向滑动返回」手势体系、小程序分包异步化加载态。这些在 Web 端以等价或更优的 Web 范式替代（见各节）。
>
> **数据字段引用约定**：本手册涉及「读取数据字段」的需求点，字段真源与小程序版**完全一致**（均来自 `data/*.json` + 运行时结构 `packages/shared`），本章不重复罗列逐字段映射，统一引用小程序 PRD 各页「数据字段引用」章节为权威来源；本章仅在 Web 端有差异处（如列表移动端卡片字段取舍）单独说明。

## 0. 运行形态与响应式总览

- **形态**：响应式 Web 网站（非小程序）。同一套代码在手机浏览器（竖屏）、平板、桌面浏览器均可用；移动端 Safari / 微信内置浏览器均可直开（纯静态资源，无脚本强依赖的渲染关键路径）。
- **信息架构（路由）**：<b>严格对齐小程序框架</b>——全局导航只有「首页 / 学校」两项（对应小程序原生 tabBar 的两 Tab），不再设集团关联 / 荣誉榜 / 小学·初中·高中明细等独立导航项。
  - `/` 首页（七区中小学·高中合并地图，核心入口；含搜索 / 筛选 / 学校卡抽屉）
  - `/school/:name` 学校详情（多学段 tab 在详情内切换：高中 / 初中 / 小学；含招生 / 升学 / 指标等模块）
  - **小学 / 初中 / 高中 明细列表**：不是独立页面，而是「学校」详情内的**学段分段控件**切换（`/school/:name?stage=high|middle|primary`），与小程序「学校 Tab 内学段切换」一致。
  - 说明：`apps/web` 历史遗留的 `/primary` `/middle` `/high` `/linkage` `/awards` 路由不在本框架的 Tab 体系内；如需保留，仅作为二级入口（如学校详情内深链），不在主导航/底部 Tab 出现。
- **断点策略**（Web UI 稿中落地）：
  - **桌面 Desktop ≥ 1024px**：左侧固定导航栏（品牌 + 菜单）+ 顶部全局条（品牌 + 紧随其后的全局搜索框 + **等高「搜索」主按钮**，高 36px；<b>搜索框为空时按钮隐藏、输入后出现</b>，同小程序交互）；<b>定位入口不占顶部条</b>，改为<b>地图右下角悬浮定位按钮</b>（FAB）；地图与详情以「地图 + 右侧抽屉」同屏呈现；列表以完整数据表呈现。
  - **平板 Tablet 768–1023px**：左侧可收起导航（或顶部汉堡）；地图全屏 + 浮层；详情以全屏页或近全屏抽屉；列表表格在窄处启用横向滚动。
  - **手机 Mobile < 768px**：底部 Tab 栏（**首页 / 学校**两项）+ 顶部品牌条；地图全屏 + 顶部浮层搜索筛选；点击点位弹**底部抽屉**（半屏）→ 点「展开详情」进入**全屏详情页**（路由 `/school/:name`）；列表（学段分段）以卡片化或横向滚动表格呈现；筛选以**底部抽屉**承载三列下钻。
- **URL 即状态**：筛选条件、选中学校、当前学段 tab 等关键状态同步到 URL query（`?district=&stage=&mech=` 等），支持刷新保留、分享深链、浏览器前进/后退。

## 1. 全局需求（跨页面）

### 1.1 产品与品牌
- **站点名称**：广州学途。
- **主题色**：知性蓝 `#2F5CD6`（主操作 / 品牌）；色阶见 Web UI 稿「设计基础」。
- **学段分色（仅用于地图点位与图例，UI 自定，不沿用项目老代码 `STAGE_COLOR`）**：
  - 小学蓝 `#2F5CD6` ｜ 初中橙 `#E8850C` ｜ 高中绿 `#0F9D58`
  - 多学段点位按所含学段「扇形拼圆」（2 学段各半圆 / 3 学段各 1/3 圆）。
- **标签四类色**（由知性蓝延展，全局通用）：
  - 行政区：底 `#EEF3FE` / 字 `#3A62C8`
  - 学段：底 `#E9F6FB` / 字 `#1F7A9B`
  - 示范等级：底 `#F1EDFD` / 字 `#5B49C9`
  - 办学性质：底 `#E9F7F0` / 字 `#1F7A55`
  - 招生方式机制标签：底 `#F2F6FE` / 字 `#254BAE`（无独立描边，并入通用标签体系）。

### 1.2 导航体系（替代原生 tabBar / 胶囊，框架对齐小程序两 Tab）
- **框架原则**：全局导航只有「首页 / 学校」两项（与小程序原生 tabBar 一致）。小学 / 初中 / 高中不是独立导航项，而是「学校」Tab 内的**学段分段控件**；集团关联 / 荣誉榜不作为主导航项（如属内容模块，置于学校详情内，不出现在 Tab 栏 / 侧栏）。
- **桌面**：左侧固定侧栏（`width≈240px`）+ 顶部全局条。侧栏含品牌「广州学途」+ 导航项：**首页、学校**；当前项高亮（知性蓝浅底 + 左侧色条）。顶部条含品牌、全局搜索框与**显眼的「搜索」主按钮**（知性蓝实心胶囊，与搜索框同高 36px、间距 8–10px 并排，点击即执行搜索）；**不设固定「开启定位」入口**（原右侧常驻入口已移除，定位改为地图内悬浮按钮，见 1.5）。顶部条在首页 / 搜索 / 筛选 / 学校页 / 详情页**全局常驻**。
- **移动**：顶部品牌条（左「广州学途」+ 右「搜索」图标）+ **底部 Tab 栏**（**首页 / 学校**两项，当前项高亮）。搜索点击后进入**全屏搜索覆盖层**（返回 + 输入框 + **「搜索」实心按钮**）；定位同样不占顶部条，用**地图右下角悬浮定位按钮**。「学校」Tab 内以**分段控件**切换 小学 / 初中 / 高中（与小程序一致）。
- **无微信系统胶囊**：浏览器自带地址栏/工具栏即系统层；Web 内所有关闭/返回均用页面内控件（× 按钮、返回箭头、ESC 键、点击遮罩、浏览器后退）。

### 1.3 标签展示规则（全局，沿用小程序）
① 行政区标签**固定全名带「区」字**（如「荔湾区」）；② 同一学校含多个学段时按学段**拆成多枚独立学段标签并排**（如「小学」「初中」），不合并写成一枚「初中/高中」；③ 同一类别多个取值一律拆成多枚标签；④ **详情卡例外**：多学段详情卡头部「学段」标签只展示当前选中 tab 对应学段（tab 条本身罗列该校全部学段）。

### 1.4 表单（表格）统一规范（跨页面通用，沿用并补充 Web 降级）
适用范围＝学校详情的录取明细表 / 第一批招生表 / 第二批招生表 / 学校页列表表单。核心规则（与小程序完全一致）：
- ① 表头与数据行**共用同一套网格列定义**；数值列（名额 / 录取最低分 / 计划人数）的**表头与数值一律右对齐**。
- ② 窄列只给够用宽度（约「表头字数×字号」），余下宽度全部让给第一列校名；窄列内数值紧随表头、不留空列。
- ③ 第一列校名尽可能占宽、单行展示（`text-overflow:ellipsis`），点进详情可见全名。
- ④ 分组行（关联校区 / 生源小学 / 共享计划校区）：学段标签、「当前查看」胶囊**紧跟校名、不右对齐**；校名按实际字数展示，仅当标签多或校名过长时收缩截断。
- ⑤ 字段行（字段名 + 填充值）：左字段名**定宽 130px**（须容纳最长字段名「省市属高中录取名额」9 字），右侧填充值，间距约 24px；同一模块多行字段值靠同一列起排。
- **Web 响应式降级**（新增）：桌面端表格完整呈现并 sticky 表头；移动端（<768px）明细表降级为「卡片行」（每行即一条记录，字段名+值两列小字），或保留原网格但在容器 `overflow-x:auto` 内横滑（5 列最低分表采用横滑，首屏提示「可向左滑动查看更多列」）。

### 1.5 定位（Web Geolocation，替代 wx.getLocation）
- **Web 能否定位：能**。浏览器 `navigator.geolocation` 在 **HTTPS（或 localhost）** 下可用，需用户授权；拒绝时降级为默认视野，功能不受影响。因此定位能力**保留**，但<b>入口从顶部条移除</b>——顶部条右侧常驻「开启定位」按钮过于抢眼、且与「地图内操作」的语义不符，改为**地图右下角悬浮定位按钮（FAB）**：圆形白底（38–40px）+ 定位准星图标 + 阴影，桌面距边 14/44px（避开底图版权行）、移动贴地图右下（距底 82px，避开图例与底部 Tab）；点击即走下面的授权 / 定位流程。
- **触发**：点击**地图右下角定位按钮（FAB）**直接调用 `navigator.geolocation.getCurrentPosition`；**页面不自绘任何授权 UI**——由浏览器/系统弹出原生权限弹窗（桌面 Chrome/Edge 挂地址栏下方，样式如「gz-xuetu.cn 想要 · 获取您的位置 · 在访问期间允许 / 仅这一次 / 一律不允许」；移动端 iOS Safari 为居中系统对话框，微信内置浏览器样式随宿主），样式与交互由浏览器/系统接管，前端仅监听结果回调。
- **授权结果处理**：
  - 允许 → 地图自动缩放到「当前定位点 + 最近的一所可见学校」都能框入的视野（缩放上限约 `scale 14` ≈ 1.3km 兜底跨度），显示当前位置标记；学校页列表按「定位区置顶 + 其余区由近及远」排序；FAB 切换为「已定位」实心态。
  - 拒绝（用户选「不允许 / 一律不允许」或浏览器策略拒绝）→ 保持默认中心城区视野，不影响其他功能；FAB 保持未定位态，可随时再点重试（浏览器会在地址栏保留站点权限开关，可随时改授权）。
- **静默策略（与小程序不同）**：浏览器自身管理位置权限与「不再询问」；Web 端**不再实现「30 天拒绝静默期」**逻辑，改为：本次会话内不再自动触发定位（sessionStorage 标记）；用户可在**地图右下角定位按钮**随时重新发起。合规口径同小程序——站点需在隐私政策中声明位置信息用途。
- **能力不可用兜底**：`navigator.geolocation` 不存在、非 HTTPS、或 API 超时（建议 8s）→ FAB 置灰 + 首次点击 toast「当前浏览器不支持定位，可手动搜索或选择区域」，不隐藏图标以外的其他功能。
- 定位为端上能力，无数据表字段。

### 1.6 地图默认视野
广州中心城区中轴线（珠江新城 — 广州塔一带）。多学段点位合并、图例（含「多学段」条目）口径同小程序 01 第 9 条。

- **底图**：与小程序一致使用**真实地图底纹**（不用纯色/纯渐变占位）——UI 稿内嵌广州越秀区局部真实底图（示意，© OpenStreetMap contributors），右下角保留版权小字；生产实现建议接入高德 / 腾讯地图 JS API 的矢量底图（含道路、水系、绿地、路名与 POI），缩放 12–17 级。点位为 GCJ-02，无需坐标转换。
- **地图控件层级**：地图 > 点位 > 悬浮控件（筛选胶囊 / 图例 / 定位 FAB / 版权小字）。定位 FAB 恒在最上层（不被弹层遮挡），弹层 / 抽屉打开时随地图缩小而重新贴边。

### 1.7 筛选栏胶囊规则（全局，沿用）
三个维度胶囊：区域 / 学段 / 办学性质（学校页另加 校园荣誉 / 招生机制 / 指标 / 学校分类 / 排序，见第 12 节）。规则：多选维度显示维度名、单选维度显示选中内容；所有胶囊**不显示已选数量角标或数字**；「区域」胶囊展开为**三列下钻面板**（见第 4 节），「学段」「办学性质」为选项组切换（见第 5 节）。

## 2. 首页 / 地图层（替代小程序 01 / 06）

1. 首页以整屏真实地图为背景，按真实地理位置预置学校点位（小学 / 初中 / 高中分色，多学段拼圆）。
2. 提供悬浮搜索框入口（桌面在顶部全局条 + 地图左上浮层；移动在顶部浮层），占位「搜索广州小初高学校」；点击进入搜索（见第 3 节）。
3. 筛选栏三胶囊（区域 / 学段 / 办学性质）：桌面以地图左上浮层或右侧筛选区呈现；移动以顶部浮层呈现。点击展开对应维度面板（区域见第 4 节三列下钻；学段 / 办学性质见第 5 节选项组）。
4. 图例区（桌面左下 / 移动左下）说明点位三色 + 「多学段」含义。
5. 地图支持缩放、拖动（桌面滚轮 / 拖拽；移动双指 / 单指）。
6. **点击学校点位** → 选中态（点位放大 + 知性蓝光晕 + 常显校名气泡）+ 弹出**学校卡**：
   - 桌面：右侧**抽屉面板**（约 380px 宽，半高预览，右下角「展开详情 →」）。
   - 移动：**底部抽屉**（约 45% 屏高，预览区渐隐，右下角实心蓝「展开详情」按钮）。
7. 首次进入按默认视野展示；定位授权流程同 1.5。
8. 多学段点位合并、图例「多学段」条目同小程序 01 第 9 条。

**数据字段引用**：同小程序 PRD 01「数据字段引用」（点位来自 `data/{primary,middle,high}/schools-gz.json`，学段来自 `entities[].stage`，合并后 `MapPoint.stages`；行政区来自 `DISTRICTS`）。

## 3. 搜索与联想（替代小程序 02 / 03）

- **桌面**：顶部全局搜索框，聚焦后下拉展示「历史记录」（胶囊平铺）+「推荐搜索」（省市属高中，拼音序）+ 实时联想词；输入即联想（精确 / 模糊 / 别名三匹配，同小程序 03 排序规则：关联度 → 行政区序 → 学段序）；词条右侧显示行政区（带「区」字）+ 学段（多学段拆多枚）标签。
- **移动**：点击顶部搜索图标 → 进入**搜索覆盖层**（全屏，含返回按钮 + 输入框 + 历史/推荐/联想区 + 系统键盘自然唤起），交互等价于小程序搜索页，但不依赖 `wx.showKeyboard`（用原生 `<input>` 聚焦即可）。
- **执行搜索**：
  - 有结果 → 关闭搜索，地图定位到结果学校、点位选中并拉起学校卡（同 2 第 6 条）。
  - 无结果 → 进入异常态 A（见第 8 节）。
- **历史记录**：浏览器 `localStorage` 本地缓存，按时间倒序；「清空」触发通用确认弹窗（见第 11 节）。
- 联想词条点击 / 搜索按钮 → 执行搜索（同小程序 03 第 5 条）。

**数据字段引用**：同小程序 PRD 02 / 03（推荐搜索 `data/high/levels.json`；联想 `entities[].name/aliases`；排序 `DISTRICTS` + `STAGE_PRIORITY`）。

## 4. 筛选面板 · 区域（行政区 / 板块 · 地铁）（替代小程序 04）

1. **三列下钻结构**（与小程序完全一致，仅承载容器不同）：
   - 第一列＝维度：`行政区/板块` ｜ `地铁`。
   - 第二列＝一级项：行政区维度下＝七区；地铁维度下＝广州地铁运营线路（1/2/3/…/22/广佛线/APM 线，共 17 编号线 + 广佛线 + APM 线，站点见小程序 PRD 04 线网表）。
   - 第三列＝二级项：点区 → 该区板块列表（首行「全部 xx 区」）；点线 → 该线站点列表（无「全部」首行）。
   - 板块清单（7 区 82 板块）、地铁站经纬度口径同小程序 PRD 04。
2. **核心口径（与小程序完全一致）**：**只有行政区维度执行点位过滤**（含「全部 xx 区」＝只保留该区、视野缩放到该区外接矩形）；**板块 / 地铁站仅定位、不过滤**（点选只把相机切到邻域，七区全部点位仍展示）。定位视野口径同小程序 04 第 6 条（板块中心锚定、1.6~2.8km 一屏、地铁站 0.8km 方框）。

## 7. 学校详情页（路由 /school/:name）（替代小程序 07 / 07B / 07E）

1. **入口**：由学校卡「展开详情」或列表点校名进入，全屏独立路由页（桌面可并排地图，移动全屏）。
2. **模块（自上而下）**：招生计划（2026）→ 升学路线参考（小学）/ 中考报考情况（初中）→ 关联校区；高中态额外含 高考信息 / 第一批招生 / 第二批招生（模块清单与字段同小程序 07 / 07B / 07E）。
3. **多学段 tab**：详情页顶部（顶栏之下、校名之上）为胶囊式学段 tab 条（高中>初中>小学、带学段色点、默认主学段）；点 tab 整体刷新；tab 滚动吸顶。单学段无 tab。
4. **顶栏校名（替代滚动联动替换）**：Web 用 **sticky 顶栏**——初始显示「学校详情」，用户下滚时校名以 sticky 标题平滑显现（CSS `position:sticky` + 滚动监听或 `IntersectionObserver` 切换文案），无需小程序式的手势联动；下滑回顶还原。
5. **返回**：页面内返回箭头 / 浏览器后退 → 回到来源（地图或列表）。ESC 等价返回。
6. **链接交互**：升学路线 / 生源小学 / 共享计划校区 / 关联校区内校名为可点击链接 → 跳转地图定位并拉起该校卡（同第 6 节链路）；点当前校 toast「已在当前学校」。
7. **模块层级规范、表单规范、空状态**：完全沿用小程序 07 全局规范（一级模块标题 17px/700/近黑 + 蓝竖条 + 顶部分隔线；二级 14px/600；三级 13px/400；说明小字 `dnote`；分组盒 `grpbox`；表格 `chartbox`+`thead`/`trow`）。
8. **数据字段引用**：同小程序 PRD 07 / 07B / 07E 各「数据字段引用」（招生计划、升学路线 `xiaoshengchu_2026.json`、中考报考/名额分配、高考信息 `levels.json`、第一批/第二批 `special_matrix.json` / `scores_2026.json`、关联校区 `school_groups.json` / `education_groups.json`）。

## 12. 学校页 / 明细列表（替代小程序 12 / 12B / 12C）

> 本节为学校明细列表（小学/初中/高中三个 sub-tab），对应现有 `/primary` `/middle` `/high` 路由与 `RankingView` 等。Web 版沿用小程序框架（顶部品牌 + 学段分段 + 筛选胶囊 + 按区归类带表头表单），并按响应式降级。

### 12.1 顶部结构与导航
- 本页（明细列表）即「学校」Tab 的内容，通过**学段分段控件**切换小学 / 初中 / 高中，不是独立页面；左右侧栏「学校」高亮。
- 桌面：左侧导航高亮「学校」；页面内顶部含学段分段控件（小学/初中/高中，纯文字无学段色点）+ 筛选胶囊行。
- 移动：底部 Tab「学校」内以学段分段切换；顶部品牌条 + 筛选胶囊（吸顶）。

### 12.2 筛选维度
- **小学 tab**：区域 / 校园荣誉（2 胶囊；区域单选、胶囊固定显示「区域」不回显，已应用转浅蓝底；校园荣誉多选 4 项默认全选）。
- **初中 tab**：区域 / 校园荣誉 / 招生机制 / 指标（4 胶囊；指标单选驱动表头列名，默认区属指标比例）。
- **高中 tab**：区域 / 校园荣誉 / 学校分类 / 排序（4 胶囊；排序单选默认按 2026 分排）。
- 区域复用第 4 节三列下钻；其余维度桌面用侧栏/弹层选项组、移动用底部抽屉；胶囊不显示数量角标。

### 12.3 列表呈现
- **按行政区归类**：区名分组头（蓝竖条 + 17px 加粗、sticky、不写数量），区与区间 1px 分隔；区内学校按规则排序（小学拼音序；初中/高中按当前指标/分数降序，null 置后）。
- **区排序**：已开定位且未筛区域 → 定位区置顶 + 其余由近及远；否则固定区序（荔湾→越秀→海珠→天河→白云→黄埔→番禺）。
- **表单列**（与小程序同）：
  - 小学：学校｜校园荣誉（两列，窄列靠右；一校多荣誉每档独立行、校名仅首行）。
  - 初中：学校｜指标列（列名随「指标」切换；最低分模式 5 列横滑表，首屏提示「可向左滑动查看更多列」，表头随内容横滑、首列不冻结；区内按指标值排序）。
  - 高中：学校｜2025录取线｜2026录取线（固定 3 列，屏内完整不横滑）。
- **Web 响应式降级**：
  - 桌面 ≥1024px：表格完整呈现，sticky 表头，列全可见；5 列最低分表在容器横滑。
  - 移动 <768px：明细表降级为**卡片行**（每行一条记录：校名 + 主指标值 + 次指标值，字段名小字前缀），或保留网格但在 `overflow-x:auto` 容器内横滑（5 列表采用横滑 + 提示）。校园荣誉列在移动端不作为独立列，可隐藏或归入卡片副信息。

### 12.4 交互
- 点学校名 → 打开学校卡（桌面右侧抽屉 / 移动底部抽屉）→ 可展开详情页（同第 6/7 节）。
- 筛选结果为空 → 异常态 C 弹窗「重置筛选」。
- **数据字段引用**：同小程序 PRD 12 / 12B / 12C（`primarySchools`、`rankingMiddle`+`quotaMatrix`、`buildHighRankingGroups`、`civilizedCampusSchoolIds`、`MECH_FILTERS`/`METRIC_GROUPS`/`SCHOOL_FILTERS`/`CIVILIZED_FILTERS`）。

## 14. Web 专有交互补充（开发必读）

1. **深链与状态同步**：筛选、选中学校、学段 tab、定位区等写入 URL query；支持刷新保留、分享、前进/后退。
2. **键盘可达性**：所有可点元素可 Tab 聚焦、回车激活；模态/抽屉支持 ESC 关闭；聚焦环可见（知性蓝描边）。
3. **浏览器导航**：详情页/抽屉的打开对应路由或 history state，浏览器后退即关闭/返回；不拦截系统返回。
4. **无脚本渲染兜底**：核心布局与内容（地图点位、列表、详情文本）尽量在服务端/静态生成或首屏直出，避免「纯客户端 JS 才出内容」导致移动端白屏（移动端 Safari 对复杂脚本执行受限）。设计稿与首屏应为静态可呈现。
5. **加载态**：用骨架屏而非小程序分包异步化；首次进入地图/详情即请求数据并展示骨架。
6. **合规**：位置信息用途写入站点隐私政策；地图底图版权（如 OSM / 高德）标注于右下角。
