# merge_groups / match_poi 产物漂移修复方案

日期：2026-09-16 ｜ 状态：方案（待确认后实施） ｜ 关联：94 处重跑漂移、用户意见"只改产物不改脚本"

---

## 一、根因诊断（已实证）

### 1.1 产物与脚本彻底脱节（流程病，主因）

`data/registry/education_groups.json` 是 `scripts/merge_groups.py` 的**产物**，但其 git 历史显示被多轮**直接手改**：

- `9c93e4e / c9b4f5b / 7d45ed7 / 1779180 / d5421c4 / 4b16934 / 5b9b995 / 3479a96 / 55202c5` 共 9 次提交都改了产物
- `5b9b995` 提交信息明写"与另一Agent改动合并"——产物被多个来源混合手改
- 对比测试：**用当前 HEAD 的 match_poi.py 重跑，产物 337 个成员中 94 处漂移**（46 丢失 / 21 错配 / 2 新增 / 其余为匹配等级变化），证明产物不是任何单一脚本版本的可复现输出

### 1.2 match_poi.py 当前版三个匹配 bug（次因）

**(a) substring 泛词错配 —— 21 处错配的统一根因**

`norm()` 执行 `s.replace("广州市","").replace("广州","")`，把「广州实验中学」规约为泛词「实验中学」。substring 步骤 `n in p["norm"] or p["norm"] in n` 于是把任何含「实验中学」的成员名吸到黄埔「广州实验中学」：

| 成员（实际属白云） | 错配到 | 原因 |
|---|---|---|
| 广州市白云广大附中实验中学 | 广州实验中学 `gz-440112-87f27cf4` | 成员名含「实验中学」 |
| 广州空港实验中学(东校区) | 广州实验中学 `gz-440112-87f27cf4` | 同上 |
| 海珠晓港湾小学 | 港湾小学 `gz-440112-2898c9fa`（黄埔） | 「港湾小学」是「晓港湾小学」子串 |
| 增城新塘镇第三中学 | 广州市第三中学 `gz-440104-d9ec2dbb` | 「第三中学」泛词子串 |

**(b) alias 路径"主校 POI 缺失"退化 —— 46 处丢失的主因**

成员名命中实体别名，但实体主校 POI 在库中不存在（只有分校区 POI，如「华阳小学」只有「华阳小学(华成校区)」POI）时，2a/2b 匹配失败、2c 返回 `school_id=""` → 成员丢失（华阳、龙口西、奥林匹克、五山、华康、沙面、华侨等 46 处）。旧产物的这些值来自历史手改，非脚本输出。

**(c) merge_groups.py 未用区收敛 —— 多候选不收敛**

`55202c5` 给 `match_school` 设计了 `preferred_adcode / preferred_stage` 收敛，但 `merge_groups.py` 调用时**未传区上下文**（`subprocess.run([...match_poi.py, "/tmp/merge_names.json"])`），导致多候选（多校区 POI）时 `_pick` 直接判缺失。

### 1.3 entities.json 别名变化

`55202c5`（3479a96 起）改动 entities.json 30376 行，删除了「广州市白云区金广实验学校」等权威别名（原为防抢名），使旧产物依赖的别名匹配失效（金广实验 `f501b6b5` 由"变体命中"变"7区缺失"）。

## 二、修复方案（分阶段，每阶段有独立验证）

### 阶段 0：基线固化（先止血，半天）

1. 提交当前工作区（本轮品牌 school_id 修复 + 报告）→ 产物现状入库，漂移清单有可比基线
2. 新增 `scripts/check_groups_drift.py`：读产物 → 调当前 match_poi 全量重算 → 输出 `丢失/错配/新增` 三类差异清单（JSON+Markdown），作为后续每次重跑的审阅工具
3. **验证**：脚本对当前状态输出 94 处差异清单（与本次诊断一致），且 `git diff` 无产出

### 阶段 1：匹配器修复（scripts/match_poi.py）

1. **泛词子串防护**：substring 步骤先做"核心词提取"——成员名与 POI norm 各自去掉泛词后缀（实验中学/中学/小学/学校/附属/第X中学等）后比较核心子串；并要求子串长度 ≥ 4 且非纯泛词；候选收敛加同区优先
2. **alias 分校区回退**：2b 失败后、2c 兜底前，增加"实体前缀 + 同区"找分校区 POI（「华阳小学」→「华阳小学(华成校区)」）
3. **无上下文收敛**：`_pick` 在无 preferred_adcode 时按「主 POI（无括号）唯一 → 同区唯一 → 前缀唯一 → 全局唯一」收敛，多候选不再一律缺失
4. **验证**：`python3 scripts/match_poi.py /tmp/mtest.json` 对 12 个回归用例（金广实验、广大附中实验中学南/星汇金沙、云雅、华阳、晓港湾、蒋光鼐三元坊、西关实验海北、新塘三中、广州实验中学不得误匹配、空港实验中学、京溪）全部正确

### 阶段 2：别名数据修复（data/registry/entities.json + 数据质量测试）

1. 恢复关键权威别名：「广州市白云区金广实验学校」→ 金广实验小学 `f501b6b5`（仅在无抢名冲突时恢复，若与其他实体冲突则改为在 partial 成员显式 poi_name 桥接）
2. 清理短名/泛词别名（如纯「实验中学」类），杜绝 substring 吸附
3. `scripts/data_quality_test.py` 新增规则：
   - 别名 norm 不得为纯泛词（长度 <4 或仅含 中学/小学/学校/附属 等）
   - 同一 norm 别名指向多个实体时，必须同 adcode（跨区即报错）
   - 产物成员 `school_id` 必须能反查到 entities 中同名校实体（一致性）
4. **验证**：数据质量测试项数增加且 0 失败

### 阶段 3：全量重跑 + 94 处逐项审阅（1-2 天，核心）

1. 修好脚本+数据后重跑 `merge_groups.py`
2. 用阶段 0 的 `check_groups_drift.py` 输出新漂移清单，逐项分类处置：
   - **真错配**（广州实验中学×2、港湾小学、蒋光鼐三元坊/文昌、西关实验海北/龙溪、新塘三中、晓港湾等）→ 数据/匹配器再修，直到归零
   - **更准**（主校优先类：乐贤坊、西关培正、仲元、开发区二小北/东校区、三元里、京溪、清华附智谷等）→ 确认后采纳为新基线
   - **恢复命中**（金广实验、华阳、龙口西等 46 处丢失）→ 必须全部找回且 school_id 正确
3. 审阅确认后：重跑 `npm run check`（40/40 + 数据质量）、详情页抽样（星悦/星汇金沙/云雅/金广实验）、快照更新、compact 重跑
4. **验证**：漂移清单只剩"已人工确认采纳"项；`npm run check` 全绿

### 阶段 4：流程闭环（防复发，关键）

1. **产物禁止手改**：README/CONTRIBUTING 写明数据流（partial/brand_groups/entities → merge_groups.py → education_groups.json → compact.mjs → web），产物只由脚本生成
2. **CI 一致性校验**：`npm run check` 增加一步——重跑 merge_groups 到临时文件，与入库产物 diff，非空即失败（提醒"改了源忘了重跑"）。**注意**：此检查须在阶段 3 重跑落定后才启用，否则当前产物必然失败
3. 新增学校/归属的标准流程：改源（partial 成员 / brand_groups school_ids / entities 别名）→ 重跑 merge_groups + compact → check_groups_drift 审阅 → 提交
4. 本次 brand 分支教训同步：brand_groups.json 是真源（无生成脚本），school_id 外键机制已落地，今后品牌归属只加 school_ids，禁止 poi_names 名字匹配

### 阶段 5：回归测试固化

1. `scripts/test_match_poi.py`（单测）：12 个用例覆盖诊断出的每类 bug
2. detail-model 覆盖断言维持 67（school_id 外键实体纳入回归）
3. 快照机制保留（按名漂移仍受控）

## 三、需要你拍板的决策点

1. **阶段 1 的匹配策略**：substring 泛词防护 + 主校优先收敛属于匹配器行为变更，会改变部分成员的匹配结果（21 处错配里约一半是"更准"）。是否同意按"宁可缺失不跨区错配"为原则？（推荐：是，缺失可由 partial 显式 poi_name 补救）
2. **entities 别名恢复**：`55202c5` 删除的别名（如金广实验学校）恢复时若与其他实体冲突，优先采用"partial 成员显式 poi_name/school_id"桥接而非别名——是否同意？（推荐：是，别名保持最小集）
3. **CI 一致性校验**：阶段 4 启用后，任何改源不重跑都会让 check 失败。是否接受这个约束？（推荐：是）
4. **实施范围**：本方案阶段 1-3 需要动 match_poi.py 匹配逻辑 + entities 别名 + 全量重跑审阅。确认后我按阶段 0→5 顺序实施，每阶段交付验证结果。
