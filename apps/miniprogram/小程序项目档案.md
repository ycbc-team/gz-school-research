# 小程序项目档案 — 上学指南针（gz-school-research）

> 维护规则：每轮交付前 Read 旧档 → 更新 → Write 写回。本档案不含任何 AppID / 密钥明文。

## 项目概况
- **项目名**：上学指南针（广州 7 区幼升小 / 小升初升学路径调研工具）
- **主体类型**：**个人主体**（用户 2026-11-03 确认）—— 个人无微信认证费，但教育子类目/位置能力类目受限，需走「工具-信息查询」类目
- **AppID 环境**：已配置于 `project.config.json`（appid 已写入，非游客占位）；发布环境=正式环境
- **定位**：离线数据型工具小程序，无后端、无登录、无支付，数据随包内置

## 技术栈
- 微信原生（WXML / WXSS / JS），基础库 libVersion 3.17.2
- Monorepo 复用 `@gz/shared`：经 `npm run build:shared` + `npm run build:mp` 产出 `apps/miniprogram/shared/`（cjs）与 `apps/miniprogram/data/`（cjs 模块）
- `shared/`、`data/` 为**构建产物、git 忽略**，但本地存在即会被开发者工具上传（无需在 DevTools 内"构建 npm"）
- 地图：原生 `<map>` 组件（腾讯底图，GCJ-02 直用）
- 分包：`pages/school-detail`（详情页），preloadRule 由首页预下载

## 待办与已知问题
- ⚠️ **类目选择（个人主体）**：选「工具 → 信息查询」最稳（个人可开、无需资质）；**不要选教育子类目**（个人无资质会被秒拒）。审核备注强调"广州本地学区信息查询工具，数据来自公开资料整理仅供参考"
- ✅ **getLocation 已处理（2026-11-03·方案A）**：个人主体上传报「接口无权限：wx.getLocation」，已删 `app.json` 的 `requiredPrivateInfos` 与 `permission`；`pages/index/index.js` 顶部加 `const LOCATION_ENABLED = false`，`maybePromptLocation()` 首行直接 return 关闭启动定位引导。地图/筛选/详情全保留，仅失去"定位到我附近"。**恢复方式**：升级企业主体并申请到位置接口后，把 `LOCATION_ENABLED` 改回 `true` 即可（locTip 弹窗代码仍完整保留）
- ✅ **隐私指引已定稿（2026-11-03）**：移除 getLocation 后 App 不再收集任何用户信息 → 后台《用户隐私保护指引》改为「未以任何方式处理用户的任何信息」提交。App 内 `pages/privacy` 文案本就写明"不获取任何地理位置信息、仅本机搜索记录"，与现状一致 ✅，无需改
- ⚠️ **隐私协议后台配置（必做）**：代码 privacy 页已就绪，但必须在 mp.weixin.qq.com 后台「设置→服务内容→用户隐私保护指引」填写并发布，否则审核必驳回
- 地图 marker 未聚类（全量点位渲染），数据量可接受则暂不上
- 发布前必须本地跑 `npm run build:mp` 确保 `shared/`、`data/` 产物齐全（白屏根因）
- 备选升级路径：若确需 getLocation 稳定可用或想走教育类目，需将主体升级为企业/组织并完成微信认证（用户自行决定）
- **名称/搜索状态（2026-11-03）**：原名不合规 → 已改为「上学指南针」并通过名称审核；但"通过名称搜索"开关仍显示"涉嫌违规，已被限制"（旧名遗留），需后台申诉/刷新解除。搜索受限不影响发布与使用（二维码/分享可进）
- **小程序备案（强制·必做）**：工信部要求，未备案无法发布上线。个人主体可备案（身份证+手机号+人脸核验，免费）。入口：后台「设置→基本设置→小程序备案」；服务内容须如实填"学区/学校信息查询"，与功能一致
- ✅ **地图改为常驻不销毁（2026-11-04 优化，替代 wx:if 销毁）**：原先全屏详情用 `<map wx:if="{{!cardFull}}">` 销毁地图，全屏↔半窗每次都要重建原生层 + 重载底图，观感卡顿。现改为常驻 + `.map.offscreen { top:100vh; bottom:auto; height:100vh }` 整体移出视口（**用 top 位移而非 transform，原生组件对 transform 支持不稳**），`cardFull` 只切 class 不销毁组件。连带：`onCardMode` 值未变直接 return、不再重建 mapCtx；`afterMapRebuild` 简化成单次 80ms 重推相机（原 260/620ms 双推是为等原生层重建）；`.page.fullview` 全屏态白底，卡片展开动画期间不再露深灰块。真机验证点：全屏↔半窗来回切换时地图是否无白块/无闪烁、相机位置是否保持。
- ✅ **全屏详情点「升学路线参考」学校后卡片"先全屏再掉半窗"（2026-11-04 修复）**：`.scard` 有 `transition: height .22s ease-out`，换学校时 `rootStyle` 从 `winH` 改到 `cardH` 会被演成过渡动画；且旧代码先 `applyStage()` 单独渲染内容（此时 mode 仍是 full），多出一帧「新学校内容 + 全屏高度」。修法：`applyStage(stage, extra)` 新增 extra 参数，把详情内容、`mode: half`、`rootStyle: height:cardH;transition:none` 合并进**同一次 setData**，`_restoreAnim()` 120ms 后恢复正常过渡（不影响手势展开/收起），`detached` 清 `_noAnimTimer`。铁律：**任何"换学校"都必须走这条合并渲染路径，别把内容与高度拆成两次 setData。**
- ✅ **全屏详情里点「升学路线参考」学校后地图灰屏（2026-11-04 修复）**：根因是 `cardFull` 未复位——全屏时 `<map wx:if="{{!cardFull}}">` 已销毁，`school-card._init()` 换学校把 `mode` 复位为 `half` 却没调 `notifyMode()`，页面 `cardFull` 永远停在 `true`，地图区域只剩 `.page` 底色（#2B3444）。修法：① `_init()` 在 setData 之后补 `notifyMode()`；② 首页 `showCard()` 主动 `setData({card, cardFull:false})` 双保险，并在地图重建后 `afterMapRebuild()`（260ms/620ms 两次）重推相机，避免点位被半窗卡遮住；③ 关联链接校名带「广州市xx区」前缀时按 id→全名→别名→包含逐级匹配（`findPointByName`），不再静默无反应
